# Bloom · AI CMO 워크스페이스

대화·일괄 제작으로 실제 MP4를 만들고, 실험 조건과 실제 성과를 저장해 다음 광고 기획으로 연결하는 로컬 앱입니다. AI CMO의 제작·관측·검토 흐름을 구현하며, 유료 광고 자동 집행이나 매체·쇼핑몰 자동 동기화는 포함하지 않습니다.

## 실행

Node.js 22.9 이상이 필요합니다. 애플리케이션·서버·운영 스크립트는 TypeScript로 작성합니다. 처음 실행할 때 `npm ci`로 컴파일러·타입 정의·의존성과 MP4 렌더링용 FFmpeg를 설치합니다. npm 설치 과정에서 현재 OS용 FFmpeg 실행 파일을 다운로드합니다.

```sh
npm ci
npm start
```

`npm start`는 TypeScript를 먼저 빌드하고 `dist/server.js`를 실행합니다. 빌드 오류가 있으면 서버를 시작하지 않습니다. [http://localhost:4174](http://localhost:4174)에 접속하세요. macOS에서는 `실행.command`를 더블클릭해도 됩니다. 이전 버전의 4173 포트는 정적 화면 서버이므로 새 주소를 사용하세요. 다른 포트는 `PORT=4180 npm start`로 지정합니다.

## TypeScript 개발 구조

- `src/app.ts`, `src/admin.ts`: 브라우저 앱과 운영 설정 화면
- `src/server.ts`: HTTP 서버와 API
- `src/domain.ts`: 광고·영상·실험·성과와 API 응답의 공통 타입
- `src/director.ts`, `src/batch-plans.ts`, `src/videos.ts`: AI 기획과 실제 렌더링
- `src/performance.ts`, `src/instagram.ts`, `src/operator-config.ts`: 성과·게시·운영 설정
- `src/scripts/check-ops.ts`: 운영 설정 검사

`npm run check`는 서버와 두 브라우저 진입점을 타입 검사하고, `npm run build`는 실행용 JavaScript를 `dist/`에 만듭니다. 브라우저는 `/app.js`, `/admin.js`에서 빌드 결과를 받으며 TypeScript 원본과 서버 빌드 파일은 HTTP로 노출하지 않습니다. `dist/`는 Git에 포함하지 않습니다. 브라우저 코드를 수정한 뒤에는 빌드를 다시 실행하세요.

브라우저 파일은 기존의 클래식 스크립트 방식으로 빌드하고 서버는 Node ESM으로 빌드합니다. 런타임 입력 검증은 유지하며 TypeScript 타입으로 대체하지 않습니다. 레거시 UI의 점진적 타입 전환을 위해 전체 프로젝트의 `strict` 모드는 아직 활성화하지 않았습니다. 테스트 하네스는 `.mjs`로 유지하고 실제 빌드 결과를 대상으로 검증합니다.

## 성과 실험과 학습

**성과 실험** 메뉴에서 제작 이후의 업무를 이어갑니다.

1. 브랜드·상품 식별명·타깃·채널·랜딩·전환 기여 기준, 목표 CPA·실험 총예산·광고비 전 공헌이익률과 기간을 설정합니다. 같은 브랜드·채널의 광고를 최대 5개 선택합니다.
2. 실험 등록 시 문구·장면 기획·사진 버전·영상 작업 ID를 복사해 보관합니다. 소재를 수정해도 과거 기록은 바뀌지 않습니다. 같은 광고의 기간이 겹치는 실험은 등록을 거절합니다.
3. 실제 매체에서 집행한 일별 성과를 직접 입력하거나 CSV로 등록합니다. 현재 지원 통화는 KRW이며 노출·링크 클릭·클릭 후 구매·매출·환불·광고비와 출처를 기록합니다. 뷰스루 전환·노출 기여 구매는 클릭 후 구매와 섞지 마세요.
4. CPA·CTR·CVR·환불 반영 ROAS, `(매출−환불)×공헌이익률−광고비`의 기여이익 추정을 비교합니다. 고정비는 포함하지 않습니다.
5. 표본 부족·예산 한도·목표 CPA·기여이익을 기준으로 추가 관측·다음 가설 제작·중단 검토·확대 실험 검토를 제안합니다. 현재 표본 기준(클릭 100회·구매 10건)은 소프트웨어의 보수적 표시 기준이며 통계적 유의성 판정이 아닙니다. 예산 한도 도달 시 표본과 무관하게 집행 상태 검토를 제안합니다.
6. 사용자가 다음 행동과 이유를 기록하면 그 시점의 지표와 권고를 함께 보존합니다. **대화로 개선**에서 해당 소재를 열면 AI 대화·일괄 기획 요청에 관련 성과·조건·의사결정 요약을 포함합니다. AI 요청 시 이 요약도 연결된 OpenAI로 전송합니다.

CSV 양식은 실험 화면에서 저장할 수 있습니다. 열 순서는 바꿀 수 있지만 다음 8개 열이 모두 필요합니다. 빈 셀은 허용하지 않으며 0은 명시적으로 입력합니다.

```csv
creativeId,date,spend,impressions,clicks,purchases,revenue,refunds
```

동일 실험·광고·날짜는 합산하지 않고 갱신합니다. 한 요청의 중복 행·미래 날짜·실험 기간 밖 날짜·알 수 없는 소재·클릭보다 많은 구매·매출보다 많은 환불을 거절합니다. 여러 행 중 하나라도 잘못되면 전체를 저장하지 않습니다. 등록 이력에 출처·갱신 수·대체 전 수치를 보존합니다. 성과 변경 API는 작업 버전을 검사하고 원자적으로 저장하며, 일반 워크스페이스 저장으로 성과 기록을 덮어쓸 수 없습니다.

### 사전 성과 추정과 사후 비교

새 실험의 성과를 등록하기 전에 **성과 등록 전 기준선 저장**을 사용할 수 있습니다. 다음 조건을 모두 만족해야 활성화됩니다.

- 동일 브랜드·상품 식별명·타깃·채널·랜딩·기여 기준·통화의 종료된 과거 실험이 최소 3개
- 과거 합산 클릭 100회·구매 10건 이상, 광고비가 0보다 큼
- 대상 실험은 오늘 이후 시작하며 아직 성과가 없고, 기준선이 저장되지 않음

과거 평균 CPC와 환불 반영 객단가를 고정 가정하고 과거 CVR로 기준 CPA·ROAS와 선택 예산의 구매·기여이익 시나리오를 계산합니다. CVR에는 [NIST가 설명하는 Wilson 95% 구간](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)을 사용합니다. 이 구간은 과거 클릭 후 전환율의 통계 범위이며 **미래 성과의 예측구간이 아닙니다**. 소재 간 우열 예측, 인과 효과 추정, ROAS 보장 또는 학습된 예측 모델로 표시하지 않습니다. 시즌·가격·오퍼·집행 예산에 따른 분포 변화는 현재 모델링하지 않습니다.

기준선은 저장 시점·원본 성과 행·조건·계산값을 함께 고정합니다. 이후 과거 데이터가 수정되어도 사전 추정은 바뀌지 않습니다. 대상 실험에 성과를 등록하면 실제 CVR·기준선과의 차이·과거 범위 내외를 표시합니다. 한 실험의 범위 내 일치는 예측 정확도의 증명이 아니며, 이는 향후 예측 모델의 시간 순서 검증을 위한 기록 기반입니다. 날짜 경계는 Asia/Seoul을 사용합니다.

## 대화로 광고 제작

1. **AI 연결 설정**에서 OpenAI API 키와 모델을 연결합니다. 대화 기획과 제품 사진 이해에는 실제 AI 연결이 필요하며, 연결 오류를 샘플 응답으로 대체하지 않습니다.
2. **AI 스튜디오** 오른쪽 대화창에 제품 사진과 원하는 광고를 이야기합니다. 예: “20대 직장인에게 오트 라떼를 소개하는 따뜻한 15초 광고를 만들어줘.”
3. 챗봇이 대화 이력·브랜드·사진·현재 기획·이전 실행 결과를 참고합니다. 꼭 필요한 정보가 없으면 질문하고, 준비되면 브리프·3개 장면·문구·길이·비율·움직임을 함께 정리합니다.
4. “마지막에 구매 유도 넣어줘”, “10초로 줄여줘”, “차분하고 간결하게”처럼 수정합니다. 답변뿐 아니라 실제 렌더링에 사용하는 기획 데이터가 바뀝니다.
5. “이대로 영상 만들어줘” 또는 **영상 제작**으로 렌더링을 실행합니다. 완성된 영상의 수정 요청은 수정 기획으로 재제작하도록 AI에 안내합니다. 단순 질문은 제작 지시로 취급하지 않도록 모델에 지시합니다.
6. 중앙에서 완성 영상을 재생하고 **Export MP4**로 저장합니다. 기획이 바뀌었는데 영상이 이전 버전이면 새 기획의 미리보기를 표시하고 재제작을 안내합니다. 렌더링 완료 전에는 내보내기를 활성화하지 않습니다.

화면은 중앙 영상·오른쪽 대화·아래 타임라인으로 구성합니다. 타임라인 자막/장면을 선택하면 해당 장면을 수정하거나 완성 영상의 재생 위치를 이동할 수 있습니다. 스타일 도구에서 길이·비율·분위기·움직임을 직접 변경할 수 있고, 기획의 실행 취소/재적용도 제공합니다. 같은 세션의 기획 변경 이력은 최대 20개를 유지합니다.

대화·누적 브리프·최신 기획·도구 실행 기록은 크리에이티브와 함께 서버에 저장합니다. 라이브러리에서 작업을 다시 열어 대화를 이어갈 수 있습니다. 최근 40개 대화 메시지, 누적 브리프와 현재 기획, 최근 실행 기록, 최신 영상 상태를 모델 입력에 포함합니다. 구조는 로컬 `claw-code`의 Rust `conversation.rs`·`session.rs`에서 확인한 세션/도구 결과 분리 패턴을 참고했으며 해당 CLI를 실행하거나 의존하지는 않습니다.

## 여러 시안 한 번에 제작

1. **AI 스튜디오 → 여러 시안 만들기**에서 제품 사진·설명, 길이(6~30초), 수량(1~5개), 비율과 목적을 지정합니다.
2. 서로 다른 소구점과 광고 가설을 AI가 기획한 뒤 실제 MP4를 순서대로 제작합니다. 시안별 진행 상태·실패 원인과 완성 영상을 비교하고 저장할 수 있습니다.
3. **이 시안으로 대화하기**를 누르면 선택한 광고의 기획과 대화를 이어 수정합니다. 다른 시안은 그대로 유지합니다.
4. 대화형 편집기의 **이 방향으로 여러 시안**으로 현재 기획과 대화 제약을 참고한 변형을 만들 수 있습니다. 이전 시안 묶음도 다시 열 수 있습니다.

같은 제품 사진은 공용 자산 하나로 저장하고 각 시안이 참조합니다. 선택한 시안에서 사진을 변경해도 다른 시안의 사진을 바꾸지 않습니다. 일괄 제작은 무음이며 선택 후 오디오를 첨부할 수 있습니다. 기획 실패는 가짜 영상으로 대체하지 않으며, 저장된 기획의 렌더링 실패는 AI를 다시 호출하지 않고 재시도할 수 있습니다. 기획에는 유효한 AI 연결이 필요합니다.

### 현재 영상 제작 범위

- 제품 사진 한 장을 사용한 3개 장면의 모션 광고
- 길이 6~30초(기본 15초), 장면별 길이는 전체의 1/3
- 9:16(720×1280) 또는 1:1(720×720), H.264·30fps·yuv420p MP4
- 따뜻함/강조/간결함의 분위기와 부드러움/역동적/정적인 움직임
- 화면 제목·보조 문구, 줌·이동·페이드 효과
- 선택 오디오 파일 합성(MP3/WAV/M4A/AAC/OGG/WebM, 최대 5MB), AAC 출력

대화에서 제품 사진도 AI에 전송합니다. 사진에서 확인할 수 없는 가격·효능·할인 등을 만들지 않도록 지시합니다. 원고 생성과 제작 결과는 게시 전에 확인하세요. 새 촬영 장면 생성, 자동 음성·음악 생성, 릴스 자동 게시는 구현하지 않았으며 완료된 기능처럼 표시하지 않습니다.

음성·음악은 사용자가 파일을 첨부합니다. 영상보다 짧으면 무음으로 채우고 길면 자릅니다. “무음으로” 요청은 오디오를 제외한 제작으로 반영합니다. 선택 파일은 현재 브라우저 메모리에 있으므로 새로고침 후 같은 오디오로 재제작하려면 다시 첨부하세요. 완성 MP4의 오디오는 유지됩니다.

### 직접 편집과 저장

**이미지·원고·세부 편집 도구 열기**를 펼치면 기존 브랜드/원고 입력, 직접 작성, 이미지 미리보기, SVG/PNG/원고 저장과 상세 장면 편집을 사용할 수 있습니다. 직접 편집과 MP4 렌더링에는 AI 키가 필요하지 않습니다.

이미지 사진은 최대 10MB이며 긴 변 1600px 이하 JPEG로 변환합니다. 영상 장면 제목은 최대 42자, 보조 문구는 최대 60자이며 화면 영역에 맞춰 줄바꿈합니다. 과도한 줄바꿈은 표시 영역에서 생략될 수 있습니다. 영상에서 확인하세요.

렌더 요청은 `.bloom/video-jobs.json`, 결과는 `.bloom/videos/<작업 ID>/`에 저장합니다. 한 번에 하나씩 처리하고 진행/대기를 합해 최대 10개까지 접수합니다. 화면을 이동해도 렌더링은 계속되며 동일한 사진·기획·오디오의 요청은 기존 결과를 재사용합니다. 재시작으로 중단된 요청은 실패로 표시하며 자동 재실행하지 않습니다. 완성 MP4와 포스터 외의 임시 파일은 완료 후 제거합니다.

`ffmpeg-static`으로 OS에 맞는 렌더러를 설치합니다. 별도 실행 파일은 `FFMPEG_PATH`, 별도 폰트는 `BLOOM_VIDEO_FONT`로 지정합니다. 기본 폰트는 Noto Sans KR 600 굵기 인스턴스이며 라이선스는 `assets/fonts/OFL.txt`에 있습니다.

## Instagram 피드 게시

사용자는 **Instagram으로 로그인 → 권한 허용 → 게시 전 확인 → 지금 게시**로 연결·게시합니다. 사용자 화면에는 토큰이나 이미지 호스팅 서비스 설정을 입력하지 않습니다. 비즈니스·크리에이터 계정이 필요합니다.

1. **Instagram** 메뉴에서 **Instagram으로 로그인**을 누릅니다.
2. Instagram에서 로그인하고 계정 확인·게시 권한을 허용합니다. 완료하면 Bloom으로 돌아옵니다. 취소·권한 거절·인증 만료를 화면에 안내합니다.
3. 스튜디오에서 `Instagram` / `이미지 광고` 작업을 열고 **Instagram 게시**를 누릅니다. 계정·완성 이미지·캡션을 확인한 뒤 **지금 게시**를 누릅니다. 이미지 호스팅과 게시 요청은 서버가 처리합니다. AI 없이 직접 작성한 광고도 게시할 수 있습니다.
4. **게시 기록**에서 진행 상황과 결과를 확인합니다. 성공하면 게시물 ID와 가능한 경우 링크가 표시됩니다. 캡션은 최대 2,200자입니다.

운영자 설정이 완료되지 않았으면 로그인 버튼은 **연결 준비 중**으로 표시되며 실제 인증을 시작하지 않습니다. 현재 로컬 앱은 단일 워크스페이스이며 사용자별 데이터 분리가 있는 공개 SaaS 배포는 포함하지 않습니다.

### 운영자 설정 (사용자별 설정 아님)

서버를 실행한 뒤 **[운영 설정 화면](http://localhost:4174/admin)**에서 Meta 앱·인증 주소·Cloudinary 값을 저장하세요. 저장하면 서버 재시작 없이 Instagram 로그인 설정에 바로 반영됩니다. 사용자에게는 이 운영 설정 화면을 안내하지 않습니다.

- 설정 누락과 형식을 검사하고 Meta에 등록할 Redirect URI를 표시·복사합니다.
- Secret은 암호화해 `.bloom/operator-config.enc`에 저장하고 GET 응답·화면에 원문을 다시 표시하지 않습니다. 빈 Secret 입력은 기존 값을 유지합니다.
- `.bloom/operator-config.key`에 로컬 암호화 키를 만들거나 `BLOOM_TOKEN_ENCRYPTION_KEY`로 별도 키를 주입할 수 있습니다. 키와 설정 파일은 Git에서 제외되며 파일 권한은 0600입니다.
- 다른 창의 설정이 먼저 저장되면 저장을 거절하고 새로고침을 안내합니다. 앱 ID를 변경하면 Instagram을 다시 연결해야 합니다.
- `/admin`, `/api/admin/config`는 로컬 Host에서만 접근합니다. 이 앱은 같은 컴퓨터를 신뢰하는 단일 워크스페이스이며 별도의 운영자 계정 인증이나 멀티테넌트 권한 체계를 제공하지 않습니다.

설정값을 환경 변수로 관리한다면 `.env.example`을 `.env`로 복사해 사용할 수 있습니다. `npm start`가 `.env`를 읽습니다. 운영 화면에서 저장한 항목이 환경 변수보다 우선합니다. 암호화 키는 서버 시작 시 정해지므로 운영 화면에서 변경하지 않습니다.

다음 명령으로 누락·형식을 확인할 수 있습니다. Secret은 출력하지 않으며 미완료면 종료 코드 1을 반환합니다. 실제 Meta·Cloudinary 자격 증명이나 HTTPS 접근성을 검사하는 명령은 아닙니다.

```sh
npm run ops:check
```

설정 항목:

- `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET`: Meta 앱의 Instagram App ID·Secret (Facebook App ID와 혼동하지 마세요.)
- `INSTAGRAM_PUBLIC_ORIGIN`: 외부에서 접근 가능한 HTTPS 인증 주소. 경로 없이 `https://auth.example.com` 형식으로 설정합니다.
- `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`: 운영자 이미지 호스팅 계정
- `INSTAGRAM_API_VERSION`: 기본 `v27.0`
- `BLOOM_TOKEN_ENCRYPTION_KEY`: 선택 사항. Base64로 인코딩한 32바이트 AES 키를 서버 비밀 저장소에서 주입할 수 있습니다. 생략하면 `.bloom/instagram-connection.key`를 자동 생성합니다.

[Meta 앱 대시보드](https://developers.facebook.com/apps/)에서 Instagram 제품과 Business Login을 설정하고 OAuth Redirect URI에 `https://auth.example.com/auth/instagram/callback`을 정확히 등록하세요. 권한은 `instagram_business_basic`, `instagram_business_content_publish`만 요청합니다. 테스트 계정은 앱 역할과 초대 승인을 확인하세요. 일반 고객의 계정에 제공하려면 필요한 Advanced Access/App Review 절차도 완료해야 합니다. 앱 도메인·정책 문서 등 Meta의 운영 요건을 충족해야 하며 코드만으로 심사를 대신할 수 없습니다.

**HTTPS 리버스 프록시에는 `/auth/instagram/start`와 `/auth/instagram/callback`만 연결하고 원래 Host를 보존하세요.** 프록시는 로컬 `127.0.0.1:4174`로 전달합니다. 외부 도메인의 다른 경로/API는 서버가 거절합니다. 로그인 시작은 로컬 앱의 JSON POST에서 1분짜리 일회용 전달 티켓을 발급받은 경우에만 가능합니다. 외부 방문자가 임의로 로컬 계정 연결을 교체하지 못하게 합니다.

인증 도메인에서 Secure·HttpOnly·SameSite=Lax 쿠키로 브라우저를 묶고, 10분 유효·일회용 `state`를 확인합니다. 서버에서 인증 코드를 토큰으로 교환하고 필요한 권한과 프로페셔널 계정 유형을 검증합니다. 완료하면 같은 기기의 `http://localhost:4174`로 돌아옵니다. 인증 코드·토큰·Secret은 반환 URL과 사용자 API에 포함하지 않습니다. 프록시 로그에도 인증 쿼리 문자열을 기록하지 않도록 운영 설정을 적용하세요.

연결 정보는 AES-256-GCM으로 암호화해 `.bloom/instagram-connection.enc`에 원자적으로 저장합니다. 키 파일과 연결 파일은 권한 0600이며 Git과 작업 백업에서 제외됩니다. 서버 재시작 후 연결을 복원합니다. 복호화 키를 잃으면 다시 로그인해야 합니다. 별도 키 관리 시스템을 사용하지 않는 로컬 기본 설정은 동일 디스크의 키 파일을 사용합니다.

서버가 실행 중이면 시작 시·6시간마다·게시 전에 토큰 만료를 점검합니다. 만료가 7일 이내이고 갱신 후 24시간 이상 지났으면 장기 토큰을 갱신합니다. 이미 만료되었거나 권한을 철회한 경우 사용자에게 재연결을 요청합니다. 연결 해제는 저장된 연결 정보를 지우며 늦게 도착한 갱신 응답이 연결을 복원하지 못하게 합니다. 이미 접수한 게시 요청은 계속 처리합니다. Instagram 측 앱 권한 자체를 철회하려면 Instagram의 연결된 앱 관리에서 해제하세요.

완성 JPEG는 운영자 Cloudinary 계정에 서명 업로드한 뒤 Meta에 공개 URL로 전달합니다. 원본은 해당 호스팅 계정에 남으며 자동 삭제하지 않습니다. 릴스·스토리·캐러셀·예약 게시는 포함하지 않습니다.

게시 요청은 `.bloom/instagram-posts.json`에 먼저 접수합니다. 같은 요청 ID 또는 같은 계정·캡션·이미지의 진행 중/완료 요청은 다시 게시하지 않습니다. 실패가 확인된 요청은 새 게시 창에서 다시 요청할 수 있습니다. 응답이 끊겨 결과가 불명확하면 자동 재게시하지 않으며 **게시 상태 확인**으로 기존 컨테이너만 조회합니다. 서버 중단 후에도 게시 요청을 자동 재실행하지 않습니다. 결과 ID를 받기 전에 연결이 끊겼으면 완료 후에도 링크가 없을 수 있습니다.

공식 문서: [Instagram 로그인](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/business-login), [Meta 게시 API](https://developers.facebook.com/documentation/instagram-platform/content-publishing), [Cloudinary 서명 업로드](https://cloudinary.com/documentation/authentication_signatures).

## AI 연결과 데이터

API 키는 브라우저 저장소나 작업 파일에 저장하지 않고 서버 메모리에만 유지합니다. 서버 재시작 후 다시 연결하거나 다음 환경 변수를 설정하세요. 키를 소스 코드나 Git에 넣지 마세요.

- `OPENAI_API_KEY`: 서버 시작 시 사용할 API 키
- `OPENAI_MODEL`: 시작 시 모델 이름 (기본 `gpt-4.1-mini`)
- `PORT`: 로컬 포트 (기본 4174)
- `BLOOM_DATA_DIR`: 작업 파일 저장 폴더 (기본 `.bloom/`)

AI 생성·수정 요청은 OpenAI Responses API를 호출합니다. 브랜드 설정, 아이디어, 수정할 기존 원고와 수정 요청을 전송하며 제품 사진은 전송하지 않습니다. API 사용료는 연결한 OpenAI 프로젝트에 청구됩니다. 키 미설정·인증 실패·잔액/사용량 제한·네트워크 오류를 화면에 표시하며 샘플 결과로 대체하지 않습니다.

브랜드·사진·작업·캠페인은 `.bloom/workspace.json`에 원자적으로 저장합니다. 서버 재시작 후에도 유지됩니다. 여러 창이 동시에 수정하면 오래된 창의 저장을 거절해 다른 작업을 덮어쓰지 않게 합니다. 저장 실패 시 현재 작업을 **작업 백업**으로 내보내고 새로고침하세요. 백업 JSON은 전체 작업 원본 보관용이며 UI 가져오기는 지원하지 않습니다. 전체 작업 데이터는 요청당 12MB까지이며, 많은 사진을 쌓기보다는 결과 파일과 백업을 보관하세요.

서버는 `127.0.0.1`에만 바인딩합니다. 이 컴퓨터의 사용자를 위한 앱이며 인증·공용 호스팅 기능은 포함하지 않습니다. 정적 파일은 허용 목록만 제공해 작업 파일과 서버 코드, API 키를 제공하지 않습니다.

Instagram 테스트도 외부 서비스를 모의 처리해 연결 검증·JPEG 전달·중복 게시 방지·응답 유실 후 상태 확인을 검사합니다. 실제 AI 생성 검증에는 유효한 API 키가 필요합니다. OAuth 테스트는 실제 로컬 HTTP에서 공개 인증 Host·리다이렉트·보안 쿠키·콜백·재사용 방지·암호화 저장·재시작 복구·자동 갱신도 검사합니다.
